*Q คือคำถาม A คือคำตอบจากผม
Q: ตัว wyrmc นี้ควรทำงานแบบไหน (สำคัญที่สุด เพราะกำหนดสถาปัตยกรรมทั้งหมด)
A: Compile .wyr → bytecode แล้วรันด้วย VM ที่เขียนด้วย C11 (เร็วกว่า interpret, ง่ายกว่า native codegen)
Q: ด้าน semantics ของภาษา ต้องการให้ wyrmc ยึดตามอันไหน
A: แก้ให้ตรงกับที่ README/Docs.md เอกสารไว้ (#arrays, multi-arg print, block comments ฯลฯ) แล้วอัปเดต interpreter เดิมให้ตรงด้วย
Q: ระดับความสมบูรณ์ที่ต้องการในรอบแรกนี้
A: ครบ production-grade เลย (memory management, error handling เต็ม, ทุก feature ปัจจุบันของภาษา)
Q: README: 'Strings and arrays: #' — syntax ที่คาดหวังเดิมคือ #(1,2,3) สำหรับ array literal เอาแบบไหน
A: #(1, 2, 3) เป็น array literal แต่ index ยังใช้ arr[0] แบบเดิม
Q: print(a, b, c) แบบ multi-arg ควร print ออกมาเป็นแบบไหน
A: คั่นด้วยช่องว่าง (Python print style): a b c
Q: self-host roadmap: รอบนี้ควรวางโครงสร้างเผื่ออนาคตเท่าไหน
A: แค่ทำ bytecode format ให้เสถียร มี versioning ชัดเจน (พอสำหรับรอบนี้)
